# 桌面版：Makefile和Git的实际作用

## 1. 架构思路

引擎仍然只认识Profile、Item、Case，不依赖Qt。桌面版新增Session层，负责“修改玩家副本 → 保存 → 替换内存数据 → 发出changed信号”。多个页面订阅这个信号，余额、背包、统计便会同步更新。

Qt的信号槽可以理解为事件通知：点击按钮发出clicked信号，连接的C++函数执行开箱；Session保存成功发出changed，背包页面刷新。`QApplication::exec()`运行事件循环，处理点击、绘制与动画。

| 模块 | 变化的原因 | 可展示的工程价值 |
|---|---|---|
| 原引擎 | GUI和CLI都要开箱、交易 | 业务复用，不复制一套逻辑 |
| Session | 界面要同步和处理保存失败 | 控制层、事务提交、信号通知 |
| 背包页 | 用户要搜索、筛选、排序 | 视图与业务分离 |
| 开箱动画 | GUI需要持续刷新，不能sleep阻塞 | QVariantAnimation与事件循环 |
| 实验室 | 100万次抽样不能一次占满主线程 | QTimer分批执行，支持停止 |
| 资源文件 | UI样式不应写满C++函数 | QSS集中管理，rcc打包 |

## 2. Makefile的新任务链

普通模块：`.cpp → .o`。

包含Q_OBJECT的Session、MainWindow、RevealDialog：`.hpp → moc生成的.cpp → .o`。

界面资源：`resources.qrc + theme.qss → rcc生成的resources.cpp → resources.o`。

最终把上述对象文件加上原引擎对象一起链接到Qt6Widgets、Qt6Gui、Qt6Core，生成独立桌面程序。

### pkg-config：定位第三方库

```bash
pkg-config --cflags Qt6Widgets
pkg-config --libs Qt6Widgets
```

第一条给头文件位置等编译选项，第二条给链接参数。Makefile不硬编码个人电脑的Qt安装目录。moc/rcc默认从Qt6Core提供的libexecdir定位，也允许 `make MOC=/实际路径/moc RCC=/实际路径/rcc`覆盖。

编译器使用 `-isystem`引用系统Qt头文件，保留自己代码的严格警告；moc使用它支持的 `-I`格式。这两个工具的选项并非完全相同。

### moc：元对象编译器

Session类的头文件含Q_OBJECT和signals声明。moc读取这个类，生成Qt事件通知需要的补充C++代码。**moc不是替代g++，它先生成代码，之后仍由g++编译。** 漏掉这一步会出现元对象、信号或虚函数表等链接错误。

### rcc：资源编译器

resources.qrc列出theme.qss，rcc将样式转换为C++数据，最终链接进程序。启动后用 `:/theme.qss`读取，不依赖当前工作目录。修改QSS后，Make应重新生成资源代码、编译资源对象、重新链接，而无需重新编译游戏引擎。

### 自动依赖与并行

`-MMD -MP`和读取 `.d`继续跟踪头文件依赖。`make -j4`允许不相互依赖的任务并行；链接必须等对象文件完成。`check-qt`作为order-only前置任务做依赖检查，不会因它是伪目标就让所有目标每次都强制重建。

moc生成文件需要保留，所以用 `.SECONDARY:`避免Make把它们当作可删除的中间文件处理。Debug、Release、Sanitize分别放在不同build目录。

## 3. Git的展示重点

原版标签v1.0后，新建feature/qt-desktop，增加Qt控制层、界面模块、资源和构建规则，测试后合并。随后在feature/gui-quality补充Qt交互测试、VS Code配置和教学资料，再合并并标记v2.0。

```bash
git log --all --graph --oneline --decorate
git diff v1.0..v2.0 --stat
git show feature/qt-desktop --stat
git show feature/gui-quality --stat
```

展示的是功能演进与可追溯性，不以提交数量评价项目质量。代码只使用一个新界面功能分支，也可以有清楚的工程价值。

## 4. 课堂演示顺序（约12分钟）

1. `make check-deps`：介绍Qt、编译器、moc/rcc。
2. `make clean && make -j4`：展示普通编译、moc、rcc与最终链接。
3. 再次 `make`：没有源文件更新时无需重编译。
4. `touch gui/inventory.cpp`，然后 `make`：只重编译背包模块并链接。
5. `touch resources/theme.qss`，然后 `make`：只重建资源并链接。
6. `make run`：打开独立窗口，介绍导航与余额。
7. 领取补给 → 选择箱子 → 播放开箱动画 → 到背包锁定一件物品。
8. 搜索、按估值排序；介绍出售确认和锁定保护；导出CSV。
9. 数据页展示统计与成就；实验室运行10万次并比较理论标线。
10. `make test`：核心断言、实际CLI与Qt按钮测试。
11. Git日志图、v1.0到v2.0差异、分支合并、版本标签。
12. 打开Makefile，指出pkg-config、moc、rcc、.d文件相关规则。

`touch`改变修改时间而不改变文件内容，Git状态可以仍然干净；这恰好说明Make主要用时间判断构建过期，而Git用内容判断修改。

## 5. VS Code怎样启动

打开完整项目目录，不要只打开一个.cpp文件。Ctrl+Shift+B执行Make构建；F5执行make debug并用GDB调试 `build/debug/arsenal-desktop`。程序仍然打开独立窗口，可以在C++函数里打断点观察余额变化。

如果是无桌面的SSH服务器，正常窗口无法显示；`make gui-test`的offscreen模式用于自动测试，不是交互式窗口。课堂请用本机Linux桌面、Linux虚拟机或具备图形显示支持的WSL。

## 6. 常见问题

- `Qt6Widgets not found`：尚未安装Qt6开发包，运行README依赖安装命令。
- `could not connect to display`：没有可用的桌面显示会话，检查是否在SSH/无图形容器中。
- 中文显示方块：安装fonts-noto-cjk，重启程序。
- 按F5找不到gdb：安装gdb和VS Code C/C++扩展。
- 存档正被使用：关闭使用同一档案的终端版或另一窗口，或给 `--save`不同路径。
- 项目解压后launch.sh没执行权限：运行 `chmod +x launch.sh`，或直接 `bash launch.sh`。
