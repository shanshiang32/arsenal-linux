## 一 . 项目目的和要求（说明通过本项目希望达到的目的和要求）

本项目以Linux下的C++17多文件程序为载体，练习g++编译与链接、Makefile构建自动化及Git版本管理。要求能解释目标、依赖、命令、变量、自动变量和函数，能演示源码或头文件变更后的增量重建，并完成一次真实远程上传。

功能要求：提供虚拟积分开箱、背包查询筛选、锁定与出售、每日补给、统计及概率实验；通过存档校验和文件互斥保护数据。项目为单机教学程序，无真实支付和联网账号。

交付要求：可重建源码、Makefile、Git分支与标签、汇报PPT、按本模板组织的报告和实际测试记录。课件原文尚未提供，课程知识对应依据用户截图整理，不能声明逐页核对全部课件。

## 二 .项目开发环境（说明本项目需要的环境）

推荐开发环境：带桌面的Ubuntu/Debian、g++（支持C++17）、GNU Make、Git、Python3、pkg-config、Qt6 Widgets / Qt6 Test、moc、rcc及中文字体。README提供系统依赖安装与make run启动命令。

本次实际验证环境：Debian 13、GCC 14.2.0、Qt 6.8.2、Python3。云端没有Qt开发包及系统安装权限，使用官方签名索引下载后解压至/workspace/qt6-local，保留TLS和包校验；通过tools/cloud-env.sh激活。此路径仅为云端适配，普通桌面使用系统包。

运行数据写入XDG数据目录或--save指定路径；测试使用临时档案和Qt offscreen，无需真实桌面。尚未在各成员的Linux虚拟机、VS Code与显卡环境验证。

## 三 .项目内容（说明本项目的内容，如：问题分析、设计方案、算法、设计图等）

1. 问题分析：界面、业务、持久化职责不同，应分离模块；手工编译多个文件容易遗漏依赖，因此用Make组织构建；开发演进需要Git保存可比较和回退的版本。

2. 模块方案：include/与src/提供model、engine、storage及CLI；gui/session协调保存事务；gui/store、inventory、statistics、reveal、window分别实现商店、背包、统计实验、开箱动画和主窗口。GUI与CLI共用业务引擎。

结构：Qt页面／CLI → 引擎与模型 → 存档读写及flock。开箱流程：检查箱子、数量与积分 → 在玩家副本中抽样与结算 → 保存成功 → 更新正式数据 → 刷新界面并播放动画。保存失败则不提交内存状态，关闭动画不会撤销已入库奖励。

3. 构建算法：wildcard搜集.cpp，patsubst映射.o；模式规则逐文件编译，$<表示首依赖，$@表示目标，$(@D)表示输出目录；链接规则用$^取得去重后的全部目标文件。-MMD -MP生成.d，-include读入头文件依赖。Qt的moc、rcc也由Make驱动。

4. 版本方案：保留原包main、feature/statistics、feature/quality、feature/qt-desktop、feature/gui-quality和v0.1-core、v1.0、v2.0标签。既有历史由助手制作，用于教学演示，不作为成员实际协作证据。远程托管地址为https://github.com/shanshiang32/arsenal-linux。
